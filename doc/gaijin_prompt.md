## 2. 最终目标

在现有 FastAPI + SQLAlchemy + Alembic + Pydantic + 原生 JavaScript + SSE 工程中完成：

- 个人知识库、班级知识库、不调用知识库三种严格互斥模式。
- 服务端知识库范围守卫、用户/班级权限隔离、缓存隔离和范围审计。
- 知识库无结果时先提示“未找到相关资料”，再按策略调用联网搜索；不得自动切换另一类知识库。
- 知识库引用展示知识库名称、文档名称和命中片段；联网引用展示网页标题和链接。
- 复用现有 LLM 适配器、流式 SSE、超时和错误处理，固定使用 DeepSeek V4 Flash。
- 普通用户和前端不得选择其他模型。
- 请求失败有限自动重试：首次失败后最多再调用 2 次，即最多 3 次模型调用。
- 失败请求支持手动重新发送；流式中断请求支持继续生成；两者均保留历史、幂等和 Token 计量。
- 稳定会话链接、历史消息持久化、刷新/重登/断线/同一用户多端恢复。
- 每个用户每日 Token 限额，输入和输出 Token 均计量；角色默认额度由管理员配置。
- 请求开始预留额度，模型返回后按实际 usage 结算并释放差额；无 usage 的失败进入待对账，不使用估算值扣费。
- 管理员可即时调整用户额度，影响后续请求，不回溯历史用量；可按管理范围查看多个班级的筛选和汇总统计。
- 用户查看个人用量、额度、剩余和北京时间重置时间；管理员查看班级全班统计、明细和审计。
- 完整的可观测性、usage 对账、数据迁移、回滚、兼容发布和自动化验收。

## 4. 决策优先级与无人值守规则

发生冲突或未明确细节时，按以下优先级处理：

1. 用户已确认的需求规则。
2. `doc/知识库改进.md` 的架构、数据和接口设计。
3. 对应模块任务文件中的最小任务和完成条件。
4. 本 Prompt 的执行、测试和质量规则。
5. 现有项目代码模式和兼容性要求。

必须遵守：

- 不增加个人 + 班级联合检索模式。
- 不把个人知识库无结果自动切换为班级知识库，反之亦然。
- 不让前端或普通用户选择模型；服务端固定 DeepSeek V4 Flash。
- 多端访问仅指同一用户登录后访问自己的会话，不实现公开分享链接。
- 管理员额度调整立即影响后续请求，不重算历史账目。
- 自动重试最多 2 次；每次真实模型调用的 usage 都计入用量。
- 没有 usage 的失败进入待对账，不按估算值扣费。
- 角色默认 Token 数值由管理员运行时配置，不能擅自写死业务数值。
- 所有北京时间日切使用服务端 `Asia/Shanghai`，不信任客户端日期。
- 保守处理未知错误和跨模块冲突：优先保持数据安全、权限隔离和可回滚性。
- 不新增外部依赖，除非确认现有依赖和标准库无法合理完成；新增依赖必须固定版本、补充部署说明和离线测试替代。
- 真实 DeepSeek 服务、真实联网搜索、真实知识库、生产数据库和浏览器登录态不得成为 pytest 的必要条件；使用 Mock、离线 fixture、临时数据库和本地模拟 SSE。
- 不删除或覆盖用户已有修改；发现共享文件被其他 Agent 修改时，重新读取并合并，不使用覆盖式重写。

## 5. 工程硬约束

1. 沿用 FastAPI、SQLAlchemy 2、Alembic、Pydantic 2、SQLite/PostgreSQL 和原生 JavaScript。
2. 知识库检索必须由服务端 `Knowledge Scope Guard` 产生授权上下文后执行。

8. 现有聊天、附件、知识库上传/解析/文件夹/版本和其他业务测试不得回归。
9. 代码注释只解释非显而易见的安全、幂等、锁、事务或时区逻辑。
10. 不为通过检查而削弱类型标注、异常处理、权限验证或测试断言。

## 6. 主 Agent 编排流程

### 6.1 准备阶段

1. 完整阅读第 3 章所有资料和对应现有代码。
2. 检查工作目录、依赖、Python 入口、数据库、迁移基线和测试基线。

4. 建立模块依赖图、执行波次、共享文件所有权和数据库迁移顺序。
5. 检查是否有其他 Agent 正在修改文件；不要覆盖用户或其他 Agent 的改动。

### 6.2 子 Agent 创建规则

- M1 至 M12 每个模块必须创建一个独立子 Agent，名称使用 `gaijin_m01` 至 `gaijin_m12`。
- 受并发槽位限制时分波次创建；主 Agent始终保留一个槽位用于复核、集成和修复。
- 子 Agent 不得再把整个模块转包；只有封闭的、不写共享文件的测试研究任务才可进一步委派。
- 子 Agent 不得编辑 `doc/gaijin_tasks/progress.md`，不得勾选模块任务文件。只有主 Agent 在复核通过后更新 checklist。
- 两个同时运行的子 Agent 不得编辑同一文件。共享文件和 Alembic 迁移按所有权串行处理。
- 子 Agent 完成后必须停止写入并返回结构化报告；主 Agent 复核前不能标记完成。

### 6.3 推荐执行波次

实际依赖优先于模块编号，但建议按以下波次：

1. **Wave 0：基线和边界**：主 Agent完成 M1/M2/M4 的共享数据边界、命名、状态和迁移接口草案。
2. **Wave 1：数据与范围**：M12-T01/T02、M1、M2、M4 的模型、Schema、权限和迁移基础。
3. **Wave 2：检索与核心对话**：M3、M5；接通三种模式、无结果回退、引用和固定模型 SSE。
4. **Wave 3：可靠性与计量**：M6、M7；接通重试、恢复、继续生成、重新发送、预留/结算和日切。
5. **Wave 4：统计与前端**：M8、M9；完成用户用量、模式选择、状态、引用、重连和额度展示。
6. **Wave 5：管理员与治理**：M10、M11；完成额度配置、班级统计、审计、日志、对账和告警。
7. **Wave 6：兼容与发布**：M12 剩余任务；完成旧接口兼容、分阶段开关、迁移演练和回滚。
8. **Wave 7：全链路验收**：主 Agent完成全量 pytest、mypy、ruff、前端验证、安全测试、并发测试和文档收尾。

如果现有代码依赖要求调整波次，主 Agent可以调整，但必须在 `progress.md` 执行记录写明原因、影响和新的依赖关系。

### 6.4 单模块循环

每个模块严格执行以下循环：

1. 主 Agent读取该模块任务文件全文，建立文件所有权和依赖输入。
2. 创建对应子 Agent，传入需求路径、概要设计路径、模块任务路径、已完成依赖和允许编辑范围。

5. 子 Agent返回结构化报告，不勾选任务和总体进度。

7. 主 Agent运行受影响范围的 pytest、mypy、ruff，并检查成功、失败、边界、权限、安全、幂等和并发场景。
8. 未通过时向同一子 Agent发送具体失败信息和修复要求，修复后重新复核。
9. 只有代码、测试、完成条件和质量门禁全部满足时，主 Agent才勾选模块文件和 `progress.md` 模块状态。
10. 在 `progress.md` 执行记录追加日期、模块、变更、测试命令、结果、阻塞和自主决策。

## 9. 测试与质量门禁

### 9.1 pytest 硬门禁

每个最小任务对应的可观察行为必须有真实断言。禁止编写只验证函数能调用、只检查状态码或没有行为断言的“装饰性测试”。至少覆盖：

- personal/class/none 和非法 `all` 的范围隔离；
- 当前用户、班级成员、退出班级、管理员管理范围和越权矩阵；
- 命中、无结果、联网成功、联网失败、检索超时和不调用知识库；
- 来源引用的知识库名称、文档名称、片段、网页标题和链接；
- 模型固定、SSE 增量、事件序号、完成、失败、取消和部分输出；
- 网络错误、超时、5xx、上下文错误、最多 2 次自动重试和不可重试错误；
- 幂等重复发送、手动重新发送、继续生成和 Last-Event-ID 重连；
- 输入/输出/总 Token、并发预留、实际结算、释放差额、取消和待对账；
- 北京时间 00:00 日切、角色额度、管理员即时覆盖和已用量达到新额度；
- 用户用量、多个班级汇总、分页、待对账展示和越权查询；
- 数据库迁移 upgrade/downgrade、旧 `all` 历史展示、旧 SSE 客户端兼容；
- 日志脱敏、request ID 链路、重复 usage 回调和告警条件；
- 现有聊天、RAG、附件、知识库文件和其他业务回归。

### 9.2 测试隔离

- 不访问真实 DeepSeek、真实联网搜索、真实学校网站、生产数据库或真实用户数据。
- 外部 LLM 使用 Mock 适配器，返回成功流、部分流、超时、5xx、非法 usage 和无 usage 错误。
- 联网搜索使用本地假适配器，固定成功、空结果、超时和异常响应。
- 数据库使用项目既有临时 SQLite/PostgreSQL 测试方式；测试结束清理临时文件。
- 并发测试使用可控 barrier/锁，不依赖随机 sleep 证明行为。

### 9.3 必须执行的质量命令

主 Agent必须在项目根目录执行并记录真实输出：

```powershell
python -m pytest backend/tests -q
python -m mypy backend/app
python -m ruff check backend/app
```

如果项目存在前端测试、浏览器 QA 或专用脚本，也必须执行。可按受影响范围先执行快速命令，但最终收尾必须执行全量命令。命令失败不得勾选总体验收；环境缺失时记录真实阻塞和已执行替代检查。

### 9.4 前端验证

至少验证：

- 模式选择器在三种模式间互斥，模型选择入口不存在；
- SSE 事件按顺序渲染，未找到提示、引用、失败、额度不足和重连状态不重叠；
- 重新发送和继续生成按钮只在合法状态显示，并防重复点击；
- 刷新/重登恢复会话模式、消息、引用和请求状态；
- 用户用量和管理员统计页面的权限、分页和北京时间显示正确。

## 10. 进度维护规则

主 Agent只能在以下证据齐全后勾选一个模块任务：

1. 任务对应代码已经存在并符合模块边界。
2. 对应 pytest 测试已通过，且不是被跳过或只验证调用成功。
3. 受影响范围的 mypy 和 ruff 已通过。
4. 权限、异常、边界、幂等和并发场景已按适用性验证。
5. 数据迁移、配置或前端影响已验证。
6. 主 Agent已查看文件内容和测试结果。

更新 `doc/gaijin_tasks/progress.md` 时：

- 子 Agent只返回报告，不直接修改进度。
- 主 Agent逐项勾选模块文件的最小任务和完成条件。
- 模块全部勾选后，再勾选 progress 中对应模块。
- 跨模块检查必须在集成测试通过后勾选。
- 每次更新追加“执行记录”，包括时间、模块、命令、结果、变更、阻塞和自主决策。
- 未执行的命令写“未执行”，不得写“通过”。

建议执行记录格式：

```markdown
### 执行记录 · YYYY-MM-DD HH:mm

- 模块/波次：Mxx / Wave x
- 变更：...
- 测试：`python -m pytest ...` → 通过/失败（摘要）
- 静态检查：`python -m mypy ...`、`python -m ruff check ...` → 通过/失败
- 集成影响：...
- 自主决策：...
- 阻塞：无 / <真实阻塞>
```
