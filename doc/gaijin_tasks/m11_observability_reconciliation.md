# M11 可观测性与对账模块任务清单

> 模块目标：建立请求、检索、重试、额度、来源和待对账的可追踪性，支持故障定位和告警。
> 前置依赖：M3-M8 的事件、状态、usage 和审计字段。
> 主要目录：`backend/app/core/`、服务层日志、后台任务、监控/告警配置。

## 最小可执行任务

- [ ] **M11-T01 定义链路日志字段**：统一记录 request ID、attempt、session/message、用户、班级、scope、状态和耗时。
- [ ] **M11-T02 增加检索日志**：记录命中数量、知识库范围、缓存命中、联网回退和来源类型，禁止记录原文敏感内容。
- [ ] **M11-T03 增加模型调用日志**：记录固定模型、超时、错误码、重试次数和 usage 是否可得，不记录 API Key。
- [ ] **M11-T04 增加额度结算日志**：记录 reservation、实际 usage、释放差额、结算状态和幂等结果。
- [ ] **M11-T05 建立待对账队列/状态查询**：按 `pending_reconciliation` 查询没有 usage 的调用，记录重试次数和人工处理结果。
- [ ] **M11-T06 实现 usage 对账任务**：从可获得的供应商回执或内部结果补写实际 usage，重复执行幂等，不能覆盖已结算值。
- [ ] **M11-T07 定义告警指标**：连续重试失败、待对账积压、额度结算异常、跨范围拦截、联网不可用和模型 5xx。
- [ ] **M11-T08 加入结构化业务错误码**：统一记录并返回需求中的错误码，不让前端依赖错误文本。
- [ ] **M11-T09 实现日志脱敏**：对用户输入、文档片段、身份信息、Token/API 密钥应用字段级脱敏。
- [ ] **M11-T10 编写可观测性测试**：验证成功、失败、重试、无 usage、跨范围拒绝和重复回调都有完整链路记录。
- [ ] **M11-T11 编写异常演练脚本**：模拟模型超时、SSE 中断、联网失败、usage 延迟并确认告警和对账结果。

## 完成条件

- [ ] 任意请求可由 request ID 追踪到检索、模型、引用、usage 和最终状态。
- [ ] 无 usage 失败不会静默丢账，有可查询和可重试的对账状态。
- [ ] 敏感信息不出现在日志和告警正文中，关键异常具备监控入口。
