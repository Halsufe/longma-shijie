# M7 Token 额度与计量模块任务清单

> 模块目标：按用户和角色实施每日 Token 限额，支持预留、实际结算、待对账、北京时间日切和管理员覆盖。
> 前置依赖：现有用户/角色模型、数据库、M5 对话编排。
> 主要目录：`backend/app/models/`、新增 `token_quota_service.py`、管理员配置服务、Alembic 迁移。

## 最小可执行任务

- [ ] **M7-T01 定义 Token 计量口径**：明确 input/output/total 三项字段，模型固定为 DeepSeek V4 Flash，失败重试按实际调用计入。
- [ ] **M7-T02 创建角色额度策略表**：保存管理员、教师、学生默认每日额度、模型、启用状态、版本和更新时间。
- [ ] **M7-T03 创建用户额度覆盖表**：保存临时额度、有效范围、调整原因、操作者和审计关联。
- [ ] **M7-T04 创建每日用量汇总表**：按用户和北京时间统计日唯一，保存额度快照、used、reserved、待对账和版本号。
- [ ] **M7-T05 创建请求 usage 事件表**：保存逻辑请求、attempt、幂等键、usage、结算状态和错误状态，并对幂等键加唯一约束。
- [ ] **M7-T06 实现北京时间统计日函数**：统一使用 `Asia/Shanghai`，覆盖夏令/边界时间和服务器非北京时间环境测试。
- [ ] **M7-T07 实现原子额度预留**：锁定用户日汇总行，检查 `used + reserved < effective_quota`，不足返回 `TOKEN_QUOTA_EXCEEDED`。
- [ ] **M7-T08 实现 usage 结算**：有 usage 时按实际输入/输出结算并释放差额；校验 reserved 不可变负数。
- [ ] **M7-T09 实现无 usage 待对账**：失败未返回 usage 时记录 pending reconciliation，不按估算值扣费并支持后续结算。
- [ ] **M7-T10 实现管理员即时额度覆盖**：调整立即影响后续请求，不修改历史已用量；新额度不高于已用量时禁止新请求。
- [ ] **M7-T11 实现日切幂等初始化**：请求入口可创建新日记录，重复创建不产生重复汇总；可选定时任务预热。
- [ ] **M7-T12 增加额度审计日志**：记录调整前后值、目标用户、操作者、原因、生效时间和配置版本。
- [ ] **M7-T13 编写并发和计量测试**：覆盖并发预留、重复回调、重试计量、取消释放、日切和待对账。

## 完成条件

- [ ] 并发请求不能突破单用户每日额度。
- [ ] 所有实际模型调用均有唯一 usage 事件，重复回调不重复记账。
- [ ] 无 usage 失败请求不会被估算扣费，待对账状态可追踪。
- [ ] 角色默认额度和用户即时覆盖按北京时间正确生效。
