# M6 重试与恢复模块任务清单

> 模块目标：提供受控自动重试、手动重新发送、流式中断继续生成、幂等和断线恢复。
> 前置依赖：M1 请求/消息状态、M5 对话编排、M7 额度接口。
> 主要目录：`backend/app/services/`、`backend/app/api/routes/chat.py`、`frontend/js/api.js`。

## 最小可执行任务

- [ ] **M6-T01 定义错误分类表**：区分可重试的网络/超时/5xx/临时依赖错误与不可重试的权限、参数、上下文、额度、取消错误。
- [ ] **M6-T02 实现 `RetryPolicy`**：首次失败后最多再调用 2 次，退避时间可配置，并记录每次 attempt。
- [ ] **M6-T03 实现幂等请求存储**：以幂等键唯一约束逻辑请求，重复提交返回原请求状态，不重复创建用户消息。
- [ ] **M6-T04 持久化失败和部分输出**：失败/中断时保存错误码、错误文本、partial content 和最后事件序号。
- [ ] **M6-T05 实现自动重试流程**：重试前检查错误分类、会话锁和额度，发送 `request.retrying` 事件。
- [ ] **M6-T06 实现手动重新发送服务**：只允许当前用户对失败/未完成请求操作，关联 `parent_request_id`，重新走完整计量链路。
- [ ] **M6-T07 实现继续生成服务**：仅允许 interrupted 且有上下文快照的消息，追加内容而非覆盖原内容，关联父请求。
- [ ] **M6-T08 增加请求状态查询接口**：返回状态、部分内容、最后事件序号、重试次数和 usage 结算状态。
- [ ] **M6-T09 增加 SSE 断点续传**：支持 `Last-Event-ID` 或等效序号，越权请求不得读取事件。
- [ ] **M6-T10 处理用户取消**：取消后停止自动重试，保存 cancelled 状态，按实际 usage 结算并释放未用预留。
- [ ] **M6-T11 编写故障注入测试**：覆盖 2 次重试上限、重复提交、重连、继续生成、重新发送、取消和越权。

## 完成条件

- [ ] 单个逻辑请求最多 3 次模型调用，且每次实际调用都可追踪。
- [ ] 网络中断后可以恢复服务端已保存内容，不会重复发送原消息。
- [ ] 继续生成和重新发送均有独立请求记录、权限校验和额度结算。
- [ ] 不可重试错误不会触发模型再次调用。
