# M9 前端聊天交互模块任务清单

> 模块目标：让用户明确选择检索模式，看到可靠状态、来源和额度，并能重试、继续生成和断线恢复。
> 前置依赖：M1-M8 服务端接口，现有 `frontend/js/views/chat.js` 和 `frontend/js/api.js`。
> 主要目录：`frontend/js/views/chat.js`、`frontend/js/api.js`、相关聊天样式与组件。

## 最小可执行任务

- [ ] **M9-T01 设计三态模式选择器**：只显示 personal/class/none 的用户可理解文案，当前模式持续可见，不增加模型选择器。
- [ ] **M9-T02 接入会话模式加载和保存**：新建/打开会话恢复默认模式，切换模式只影响新消息并同步服务端。
- [ ] **M9-T03 扩展消息发送参数**：发送 `knowledge_scope`、联网开关和幂等键，禁止前端提交可选模型。
- [ ] **M9-T04 扩展 SSE 事件解析**：支持 accepted、delta、not_found、citation、retrying、interrupted、completed、failed、quota 事件。
- [ ] **M9-T05 实现状态渲染**：区分生成中、重试、断开、失败、取消、额度不足、未找到资料和完成状态。
- [ ] **M9-T06 实现引用展示组件**：知识库展示知识库名/文档名/片段，联网展示网页标题/链接，来源类型视觉区分。
- [ ] **M9-T07 实现重新发送操作**：失败/未完成消息显示按钮，调用重试接口并防止重复点击。
- [ ] **M9-T08 实现继续生成操作**：中断消息显示按钮，追加服务端返回内容，不覆盖已有部分输出。
- [ ] **M9-T09 实现 SSE 断线恢复**：记录 request ID 和最后事件序号，重连先查询服务端状态，再续传或展示最终结果。
- [ ] **M9-T10 实现刷新/多端同步**：会话打开重新拉取消息和引用，服务端状态覆盖本地临时状态。
- [ ] **M9-T11 增加个人额度展示**：显示已用、每日额度、剩余和北京时间重置时间；额度不足禁用发送并展示提示。
- [ ] **M9-T12 编写前端交互测试**：覆盖三种模式、事件顺序、失败重试、继续生成、断线、额度不足和移动端布局。

## 完成条件

- [ ] 用户不会误以为当前正在检索其他知识库，模式和来源始终可见。
- [ ] SSE 中断、刷新和重连不会重复发送或丢失已保存消息。
- [ ] 前端无模型选择入口，所有状态以服务端返回为准。
