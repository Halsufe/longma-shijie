# M12 迁移与兼容模块任务清单

> 模块目标：以可回滚、分阶段方式落地新字段、新表和旧接口兼容，最终禁止新请求隐式扩大知识库范围。
> 前置依赖：M1-M11 数据和接口设计已冻结。
> 主要目录：`alembic/versions/`、旧聊天路由/Schema、部署和回滚脚本。

## 最小可执行任务

- [ ] **M12-T01 建立迁移清单**：列出会话/消息新增字段、引用/请求/usage/额度/审计表、索引和唯一约束。
- [ ] **M12-T02 编写第一阶段数据库迁移**：先增加可空兼容字段和新表，不改变旧请求行为；验证 SQLite/PostgreSQL upgrade。
- [ ] **M12-T03 编写回滚迁移**：明确新表和字段的回滚顺序，迁移测试不得破坏已有聊天数据。
- [ ] **M12-T04 定义历史 `rag_scope=all` 兼容策略**：历史消息只读展示，新请求统一拒绝 `all`，补充迁移说明。
- [ ] **M12-T05 保留旧 SSE 兼容解析**：新增事件使用扩展字段，旧客户端至少能显示最终回答，验证事件兼容。
- [ ] **M12-T06 增加数据回填脚本**：为历史会话设置安全默认值；不重新猜测或重分类历史引用范围。
- [ ] **M12-T07 编写分阶段发布开关**：支持先上线字段/记录，再开启强制 scope 和额度拦截，配置修改有审计。
- [ ] **M12-T08 更新部署和初始化脚本**：确保迁移、角色额度策略、时区和固定模型配置在新环境可重复初始化。
- [ ] **M12-T09 执行旧接口回归**：验证会话列表、历史消息、附件、重新生成和现有 RAG 流程不被破坏。
- [ ] **M12-T10 编写上线检查清单**：包括备份、迁移、回滚、数据校验、旧客户端、跨范围测试和监控确认。
- [ ] **M12-T11 完成迁移后清理**：移除默认 `all` 路径和临时兼容分支，仅在确认所有客户端升级后执行。

## 完成条件

- [ ] 数据库迁移和回滚在支持的数据库上通过，旧聊天记录可正常读取。
- [ ] 分阶段开关可以控制强制 scope 和额度功能，发布失败可回退。
- [ ] 新请求不存在隐式扩大知识库范围的兼容逻辑。
- [ ] 上线检查清单、备份和回滚步骤经过演练。
