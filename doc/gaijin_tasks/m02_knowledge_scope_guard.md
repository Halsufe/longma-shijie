# M2 知识库范围守卫任务清单

> 模块目标：在服务端严格隔离个人知识库、班级知识库和不调用知识库模式。
> 前置依赖：M1 会话字段、现有认证、班级成员关系、`RAGService`。
> 主要目录：`backend/app/ai/retriever.py`、`backend/app/services/chat_retrieval_service.py`、认证/班级权限服务。

## 最小可执行任务

- [ ] **M2-T01 定义 `KnowledgeScope` 枚举**：只允许 `personal`、`class`、`none`，为旧 `all` 和未知值定义 `INVALID_KNOWLEDGE_SCOPE` 错误。
- [ ] **M2-T02 定义 `AuthorizedRetrievalContext`**：包含当前用户、班级、scope、可查询索引、联网策略、审计字段和缓存分区键，并设置为不可变对象。
- [ ] **M2-T03 实现个人范围解析**：只绑定当前用户个人知识库，忽略客户端传入的其他用户 ID，并添加权限单元测试。
- [ ] **M2-T04 实现班级范围解析**：校验当前用户仍是目标班级成员，只绑定该班级知识库，不允许跨班级查询。
- [ ] **M2-T05 实现 `none` 范围解析**：返回空检索授权，后续调用链可判断为跳过知识库。
- [ ] **M2-T06 接入会话和消息模式校验**：新消息模式必须属于允许枚举，历史消息只读保留原模式；模式切换不得修改历史记录。
- [ ] **M2-T07 收敛 RAG 调用参数**：所有 RAG 调用必须接收守卫生成的 context；禁止业务代码自行传 scope/user/class。
- [ ] **M2-T08 加固缓存分区键**：实现并测试 `user_id/class_id/scope/query_hash/index_version` 组合键，禁止个人与班级共用检索缓存。
- [ ] **M2-T09 记录范围审计信息**：检索请求和引用记录保存实际 scope、用户和班级信息，支持问题排查。
- [ ] **M2-T10 编写隔离回归测试**：个人模式不命中班级文件，班级模式不命中个人或其他班级文件，none 模式无 RAG 调用记录。
- [ ] **M2-T11 编写成员变化测试**：退出/移出班级后新检索立即拒绝；管理员管理范围外的班级无法被冒用。

## 完成条件

- [ ] 服务端不存在默认扩大到 `all` 的新请求路径。
- [ ] 三种模式均通过接口、缓存、日志和引用四层隔离测试。
- [ ] RAG 服务无法绕过守卫自行扩大检索范围。
- [ ] 班级成员变化会立即影响知识库访问权限。
