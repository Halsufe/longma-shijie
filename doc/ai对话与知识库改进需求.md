# AI 对话与知识库改进需求

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 文档状态 | 需求确认稿 |
| 适用模块 | AI 对话、个人知识库、班级知识库、联网搜索、Token 用量管理 |
| 指定模型 | DeepSeek V4 Flash |
| 额度重置时区 | 北京时间（UTC+8） |

## 2. 背景

当前 AI 对话功能存在以下问题：

1. 个人知识库、班级知识库和不调用知识库三种模式的边界不清晰，容易只检索某一个知识库，或检索到错误范围的数据。
2. 知识库未命中后缺少明确提示和统一的后续处理规则。
3. AI 请求失败时，对话容易中断，原消息和已生成内容可能无法恢复。
4. 对话缺少稳定、持久化的访问链接，刷新、重新登录、网络重连或多端访问时可能无法继续原对话。
5. 所有账户可无限使用模型，缺少按用户、角色配置的每日 Token 限额。
6. 用户和管理员缺少清晰的 Token 用量查询与统计能力。

## 3. 改进目标

1. 用户能够明确选择知识库模式，系统严格按照所选范围检索。
2. 知识库无匹配结果时先明确提示，再转为联网搜索。
3. 每条知识库或联网回答均可追溯来源。
4. AI 请求失败时能够有限自动重试，并保留原消息供用户重新发送。
5. 对话链接和历史记录稳定持久化，支持刷新、重登、重连及多端访问。
6. 按用户实施每日 Token 限额，并按管理员、教师、学生设置不同默认额度。
7. 用户可查看个人用量，管理员可查看所管理班级的全班统计。

## 4. 用户角色与权限

| 角色 | 知识库权限 | Token 权限 | 统计权限 |
| --- | --- | --- | --- |
| 学生 | 访问本人个人知识库和所在班级知识库 | 使用学生默认额度 | 仅查看本人用量 |
| 教师 | 访问本人个人知识库和所在班级知识库 | 使用教师默认额度 | 仅查看本人用量 |
| 管理员 | 按管理范围访问和管理班级知识库 | 使用管理员默认额度；可调整指定用户额度 | 查看所管理班级的全班统计 |

班级知识库向该班级所有成员共享。用户退出班级或被移出班级后，应立即失去该班级知识库的访问权限。

## 5. 知识库模式需求

### 5.1 模式定义

系统必须提供以下三种互斥模式：

| 模式 | 检索范围 | 禁止行为 |
| --- | --- | --- |
| 个人知识库 | 仅检索当前用户的个人知识库 | 不得检索班级知识库 |
| 班级知识库 | 仅检索当前用户所在班级的共享知识库 | 不得检索个人知识库或其他班级知识库 |
| 不调用知识库 | 不检索任何知识库 | 不得调用个人或班级知识库的检索接口、索引或缓存 |

本期不增加“个人知识库 + 班级知识库”联合检索模式，也不得在后台隐式合并两类知识库。

### 5.2 模式交互

1. 用户发送消息前可以明确选择三种模式之一。
2. 当前选择必须在界面上持续可见，不得只通过隐含状态判断。
3. 模式按会话和消息持久化；每条用户消息记录实际使用的模式。
4. 用户切换模式后，仅新消息使用新模式；历史消息保留原模式记录。
5. 刷新页面、重新登录、网络重连或多端打开对话后，应恢复该会话最近一次选择的模式。

### 5.3 服务端强制隔离

1. 前端选择不能作为唯一限制，服务端必须再次校验知识库模式和访问权限。
2. 检索请求必须携带用户 ID、班级 ID、会话 ID 和知识库范围。
3. 个人模式仅允许查询归属于当前用户的索引。
4. 班级模式仅允许查询当前用户有权访问的班级索引。
5. 不调用知识库模式不得执行知识库查询。
6. 检索缓存键必须包含用户、班级和知识库范围，避免不同范围共用缓存。
7. 检索日志和引用记录必须保存实际使用的知识库范围，支持审计和问题排查。

## 6. 无结果与联网搜索

### 6.1 处理流程

知识库模式下的标准流程为：

1. 按用户所选范围检索知识库。
2. 有匹配结果时，基于检索结果生成回答并展示引用来源。
3. 无匹配结果时，先提示用户“未找到相关资料”。
4. 提示后自动转为联网搜索。
5. 联网搜索成功后，展示基于联网结果生成的回答及网页来源。
6. 联网搜索失败时，明确提示网络资料暂时不可用，不得将模型常识伪装成知识库或联网结果。

不得因为当前知识库无结果而自动切换到另一个知识库。例如，个人知识库无结果时不得自动检索班级知识库。

### 6.2 不调用知识库模式

1. 不调用知识库模式下不得执行任何知识库检索。
2. 是否执行联网搜索由联网功能的当前产品策略控制。
3. 回答中不得展示虚假的知识库引用或将模型常识标记为知识库内容。

### 6.3 来源展示

知识库回答至少展示：

- 知识库名称；
- 文档名称；
- 实际命中的内容片段。

联网搜索回答至少展示：

- 网页标题；
- 网页链接；
- 支撑回答的相关内容或摘要。

知识库来源与联网来源必须使用不同的来源类型标识，使用户能够明确区分。

## 7. AI 对话稳定性

### 7.1 请求状态

每条 AI 请求至少支持以下状态：

- 待发送；
- 生成中；
- 自动重试中；
- 已完成；
- 失败；
- 已取消；
- 额度不足。

前端应根据状态显示明确反馈，失败状态必须提供“重新发送”操作。

### 7.2 失败范围

请求失败包括但不限于：

- 网络请求失败；
- 请求超时；
- 模型服务异常；
- 服务端错误；
- 流式输出中断；
- 上下文过长；
- 联网搜索服务失败；
- 知识库检索服务失败。

### 7.3 自动重试

1. 对可恢复的请求失败自动重试，最多重试 2 次。
2. 重试采用递增等待时间，避免短时间内连续请求故障服务。
3. 参数错误、权限不足、额度不足、上下文超限和用户主动取消等不可恢复错误不得自动重试。
4. 每个逻辑请求必须具备幂等标识，防止自动重试造成重复消息、重复联网搜索或重复扣费。
5. 自动重试耗尽后保留用户原消息，显示失败原因并允许用户手动重新发送。
6. 用户手动重新发送时创建新的请求记录，但应关联原失败请求，便于追踪。

### 7.4 流式输出恢复

1. 流式输出中断时保存已经生成的内容，并标记为“未完成”。
2. 用户可选择继续生成或重新发送。
3. 网络重连后，前端从服务端同步请求的最新状态，不得盲目重复提交。
4. 已由服务端完成但前端未收到的消息，应在重连后恢复展示。

### 7.5 稳定链接与历史记录

1. 每个对话具有唯一、持久化且可重新打开的链接。
2. 刷新页面、重新登录、网络重连和多端访问时，均能恢复同一对话及完整历史。
3. 服务端必须持久化消息内容、消息顺序、知识库模式、引用来源、请求状态和 Token 用量。
4. 每次通过链接打开对话时重新校验访问权限。
5. 禁止用户通过猜测或修改对话 ID 访问他人对话。
6. 同一对话在多端产生新消息后，各端应以服务端状态为准进行同步。

## 8. Token 限额管理

### 8.1 计量口径

1. AI 对话使用 DeepSeek V4 Flash 模型。
2. Token 用量按每日、每个用户单独统计。
3. 消耗量包含输入 Token 和输出 Token。
4. 每次请求保存输入、输出及总 Token 数。
5. Token 数以模型服务实际返回的用量数据为准。
6. 自动重试和失败请求按模型服务实际产生的用量计入，但同一次实际调用不得重复记账。
7. 联网搜索或知识库检索本身是否产生独立计费，不纳入本需求中的模型 Token 口径；如相关服务另行计费，应单独建立费用统计规则。

### 8.2 每日额度

1. 按管理员、教师和学生配置不同的默认每日额度。
2. 每日北京时间 00:00 重置当日已用额度。
3. 管理员可以为指定用户调整每日额度。
4. 额度调整必须记录调整人、调整时间、调整前后数值、原因和生效范围。
5. 各角色默认额度的具体数值由产品或管理员配置，本需求不预设数值。

### 8.3 额度校验与扣减

1. 前端发送前可预检查剩余额度，但服务端必须进行最终校验。
2. 达到每日额度后禁止发送新的 AI 请求。
3. 达到额度时提示：“今日 Token 额度已用完，请明日再试或联系管理员。”
4. 并发请求必须采用原子扣减、额度预留或等效机制，避免同时发送多个请求突破限额。
5. 请求结束后依据实际用量结算预留额度，并释放未使用部分。
6. 用户主动取消时，只记录模型服务已经实际消耗的 Token，不得扣除未发生的用量。
7. 记账失败时应进入待对账状态，不得静默丢失或重复扣减。

## 9. 用量查询与统计

### 9.1 用户端

用户可以查看：

- 今日已用 Token；
- 每日 Token 额度；
- 今日剩余额度；
- 下一次重置时间；
- 按对话统计的输入、输出及总 Token 用量。

### 9.2 管理员端

管理员可以在其管理范围内查看：

- 班级当日总用量；
- 班级成员的额度、已用量和剩余额度；
- 按用户查询用量明细；
- 按日期查询历史用量；
- 按模型汇总用量；
- 请求成功、失败和重试产生的用量；
- 用户额度调整记录。

管理员不得查看管理范围之外班级的统计数据。统计数据导出格式和数据保留期限列入待配置项。

## 10. 数据结构建议

### 10.1 对话

建议包含：

- `conversation_id`：对话唯一标识；
- `owner_user_id`：对话所有者；
- `class_id`：关联班级，可为空；
- `knowledge_scope`：`personal`、`class` 或 `none`；
- `web_search_enabled`：是否允许联网搜索；
- `created_at`、`updated_at`；
- `last_message_status`。

### 10.2 消息与请求

建议包含：

- `message_id`、`request_id`、`conversation_id`；
- `user_id`、`class_id`；
- `model`、`knowledge_scope`；
- `idempotency_key`、`retry_count`、`parent_request_id`；
- `status`、`error_code`、`error_message`；
- `input_tokens`、`output_tokens`、`total_tokens`；
- `started_at`、`finished_at`。

### 10.3 引用来源

建议包含：

- `source_type`：知识库或联网搜索；
- `knowledge_base_id`、`knowledge_base_name`；
- `document_id`、`document_name`；
- `source_url`；
- `matched_excerpt`；
- `message_id`。

### 10.4 用户额度与用量

建议包含：

- 用户 ID、角色、统计日期；
- 每日额度、临时调整额度；
- 输入、输出及总 Token 用量；
- 已预留 Token；
- 最后结算时间；
- 额度调整审计记录。

## 11. 接口改造建议

### 11.1 创建 AI 消息

服务端依次执行：

1. 校验用户和会话权限；
2. 校验知识库模式及对应资源权限；
3. 校验并预留 Token 额度；
4. 创建带幂等标识的请求；
5. 按明确范围执行知识库检索；
6. 按规则执行联网回退；
7. 调用模型并持久化消息和引用；
8. 按实际 Token 用量完成结算。

### 11.2 重试消息

- 校验原请求属于当前用户；
- 判断错误是否允许重试；
- 自动重试最多 2 次；
- 手动重发生成新的请求标识，并关联原请求；
- 每次实际模型调用独立记录用量，同时保证不重复记账。

### 11.3 用量接口

- 普通用户只能查询本人数据；
- 管理员只能查询所管理班级的数据；
- 所有统计接口执行服务端权限校验；
- 日期边界统一按北京时间计算。

## 12. 可观测性与安全要求

1. 记录请求耗时、失败类型、重试次数、知识库范围、检索命中数量和 Token 用量。
2. 对请求失败、连续重试失败、对账异常、跨范围访问拦截和额度异常建立监控。
3. 日志中的用户输入、文档内容和身份信息应按安全规范脱敏。
4. 所有会话、检索、引用、用量和管理员调整接口均进行身份认证与权限校验。
5. 会话状态、消息状态和 Token 记账状态必须可关联追踪，支持异常对账。
6. 服务端返回稳定的业务错误码，前端不得依赖不稳定的错误文本判断状态。

## 13. 验收标准

### 13.1 知识库

1. 个人知识库模式下，接口、日志、缓存和引用中不出现班级知识库结果。
2. 班级知识库模式下，不出现个人或其他班级知识库结果。
3. 不调用知识库模式下，知识库服务没有调用记录。
4. 切换模式后，新消息使用新模式，历史消息的模式记录不变。
5. 用户退出班级后，无法继续检索或通过历史链接访问该班级的受限资料。

### 13.2 联网与来源

1. 知识库无结果时先显示未找到资料提示，再执行联网搜索。
2. 无结果时不会自动切换到另一类知识库。
3. 知识库回答展示知识库名称、文档名称和命中片段。
4. 联网回答展示网页标题和链接，并与知识库来源明确区分。
5. 联网失败时给出明确状态，不展示虚假来源。

### 13.3 对话稳定性

1. 模拟请求超时、断网、服务端错误和流式中断时，符合条件的请求最多自动重试 2 次。
2. 重试耗尽后保留原消息并支持重新发送。
3. 自动重试不会产生重复消息或重复 Token 记账。
4. 刷新、重新登录、网络重连和多端打开均能恢复完整对话。
5. 他人无法通过修改对话 ID 访问不属于自己的对话。

### 13.4 Token 限额

1. 输入和输出 Token 均被正确记录。
2. 用户达到每日额度后，服务端拒绝新请求并显示明确提示。
3. 并发请求测试不能突破每日额度。
4. 北京时间 00:00 后额度按新统计日正确重置。
5. 管理员、教师和学生的角色默认额度分别生效。
6. 管理员调整指定用户额度后立即按设定范围生效，并留下完整审计记录。
7. 用户能查看个人用量，管理员能查看所管理班级的全班统计，越权查询被拒绝。

## 14. 实施优先级

### P0：必须优先完成

- 三种知识库模式严格隔离；
- 知识库及会话权限校验；
- 消息持久化、请求幂等、失败重试和稳定链接；
- 服务端每日 Token 限额和并发防突破。

### P1：核心体验完善

- 知识库无结果提示和联网回退；
- 知识库及联网引用展示；
- 用户用量页面和管理员全班统计。

### P2：运营与治理增强

- 用量导出；
- 趋势分析；
- Token 对账工具；
- 服务异常和用量异常告警。

## 15. 待配置项

以下项目尚未给出具体值，实施前由产品或管理员配置，不在本文中擅自设定：

1. 管理员、教师和学生的默认每日 Token 额度。
2. 各类请求的超时阈值和可自动重试错误码清单。
3. 联网搜索服务、搜索结果数量、超时及合规策略。
4. 用量统计导出格式和数据保留期限。
5. 服务可用性目标、监控指标和告警阈值。
