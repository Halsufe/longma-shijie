# 成果与社区 · 我的成果模板细化需求文档

> 文档版本：v0.1  
> 编写日期：2026-08-05  
> 适用模块：成果与社区（我的成果）  
> 关联现状：`backend/app/models/achievement.py`、`backend/app/schemas/achievement.py`、`backend/app/api/routes/achievements.py`、`frontend/js/views/community.js`

---

## 1. 文档目的与范围

本文档用于细化“成果与社区 → 我的成果”中 8 类成果各自需要填写的模板信息，并补充以下配套需求：

1. 用户可按年份查看自己当年的成果。
2. 每类成果支持上传证明材料（附件）。
3. 主界面展示“用户数据概览”，按 8 类成果统计用户填报数量。

本期落地方式（已确认）：在现有通用字段基础上，新增扩展结构化 JSON（`details_json`）承载各分类专有字段；附件继续使用 `proofs_json`；成员和指导教师只填写姓名文本，不关联系统用户。

---

## 2. 现状与改造思路

### 2.1 现状

当前 `achievements` 表为一张通用表，字段如下：

| 字段 | 说明 |
| --- | --- |
| `category` | 成果分类（8 类） |
| `title` | 成果标题 |
| `description` | 成果说明 |
| `achievement_date` | 获得日期 |
| `level` | 级别（国家级/省级/校级/院级） |
| `status` | 审核状态 |
| `is_public` | 是否公开展示 |
| `member_ids_json` | 团队成员用户 ID |
| `proofs_json` | 证明材料列表 |

前端“添加成果/编辑成果”弹窗目前对所有分类使用同一组字段：类别、级别、标题、说明、日期、是否公开。没有分类专用模板，也没有附件上传。

### 2.2 改造思路

- 保留通用字段 `title`、`category`、`status`、`is_public`、`level`。
- 新增 `details_json`：存放各分类专有字段（键值结构见第 6 章）。
- 附件上传：`proofs_json` 承载上传的文件列表，每个成果至少上传 1 份材料。
- 成员与指导教师：统一使用姓名文本字段，不做用户关联。
- `achievement_date` 不再由用户单独填写，改为由各模板中的年份/月份字段派生，用于列表展示和按年份筛选。
- `member_ids_json` 兼容保留，但不作为新的团队填写主入口。

## 3. 分类与展示名

| 分类标识 | 展示名 | 说明 |
| --- | --- | --- |
| `paper` | 学术论文 | 期刊/会议论文 |
| `award` | 竞赛获奖 | 学科竞赛、创新创业大赛等 |
| `research` | 项目课题 | 参与的科研项目、课题 |
| `patent` | 软著专利 | 发明专利、实用新型、外观设计、软件著作权 |
| `innovation` | 创新创业 | 创新项目、创业项目 |
| `organization` | 组织管理 | 学生组织、部门任职经历 |
| `social` | 社会实践 | 志愿服务、社会实践 |
| `arts` | 文体活动 | 文艺、体育活动 |

> 说明：`research` 展示名由原“科研项目”调整为“项目课题”；`patent` 展示名按需求文案使用“专利/软著”。模板内部标题文案见第 6 章，按用户提供的原文案执行。

## 4. 通用字段定义

### 4.1 通用字段表

| 字段 | 是否修改 | 说明 |
| --- | --- | --- |
| `id` | 否 | 主键 |
| `user_id` | 否 | 所属用户 |
| `category` | 否 | 8 类成果分类标识 |
| `title` | 是 | 各分类的成果名称/标题，映射见第 6 章各表 |
| `description` | 兼容保留 | 不再作为新模板主输入，列表展示时可回退显示 |
| `achievement_date` | 是 | 不再单独填写，由模板年月派生，格式 `YYYY-MM` |
| `level` | 是 | 仅竞赛获奖、项目课题、创新创业、文体活动使用，其余分类为空 |
| `status` | 否 | `pending/approved/rejected` |
| `is_public` | 否 | 是否公开展示（审核通过后展示） |
| `member_ids_json` | 兼容保留 | 仅用于兼容旧数据，新模板不再采集用户 ID |
| `proofs_json` | 是 | 附件材料列表（文件名、路径、上传时间） |
| `details_json` | 新增 | 各分类专有字段，结构见第 6 章 |
| `created_at/updated_at/deleted_at` | 否 | 时间戳 |

### 4.2 统一成果年份（用于按年份查看）

“我的成果”按年份查看时，每个成果对应一个统一成果年份，派生规则如下：

| 分类 | 统一成果年份 |
| --- | --- |
| 学术论文 | 发表年份 |
| 竞赛获奖 | 获奖年份 |
| 项目课题 | 立项年份 |
| 软著专利 | 授权年份；未授权时使用申请年份 |
| 创新创业 | 开始年份 |
| 组织管理 | 开始年份 |
| 社会实践 | 开始年份 |
| 文体活动 | 开始年份 |

> 该派生规则为推荐默认值，如某分类希望使用其他年份字段（如专利统一使用申请年份），可在评审时调整。

## 5. 通用交互需求

1. 新增/编辑入口：沿用现有“我的成果 → 添加成果/编辑成果”流程。
2. 选择分类后，前端加载该分类的专用模板，模板文案和字段按第 6 章执行。
3. 附件上传位于表单最上方，支持多份上传、预览、删除和替换；每个成果至少上传 1 份材料。
4. 所有条目必填；无值字段按各模板约定的占位值填写（“无”“forthcoming”等）。
5. 保存后进入 `pending` 待审核状态，管理员审核流程保持不变。
6. 我的成果列表支持按年份筛选（“全部”+各具体年份），年份口径按统一成果年份；列表默认按成果年份和月份倒序排列。
7. 列表展示关键信息：标题、类别、级别（如有）、年份、审核状态、附件数量。
8. 学术论文列表中，点击标题可跳转该论文的 DOI 链接。

## 7. 附件（证明材料）要求

1. 每个成果至少上传 1 份证明材料，可上传多份。
2. 各类成果建议的证明材料示例：
   - 学术论文：论文首页、录用通知、检索截图。
   - 竞赛获奖：获奖证书、比赛通知、成绩公示截图。
   - 项目课题：立项书、结项书、批准文号文件。
   - 软著专利：授权证书、受理通知书、软著证书。
   - 创新创业：项目立项文件、结项材料、营业执照或获奖证明。
   - 组织管理：任职文件、聘书、考核评定材料。
   - 社会实践：实践单位证明、志愿服务时长记录、活动照片。
   - 文体活动：获奖证书、活动证明、秩序册、照片。
3. 附件格式建议为 PDF/JPG/PNG；单文件大小上限沿用系统配置，建议默认不超过 20MB（可配置）。
4. 附件在 `proofs_json` 中记录文件名、存储路径/键、上传时间和材料说明；支持在编辑时查看、删除、替换。
5. 附件在审核页随成果详情一并展示，供管理员审核。

---

## 8. 按年份查看

1. “我的成果”页提供年份筛选控件，包含“全部”和各具体年份，默认选中当前年份（可配置）。
2. 年份口径：按第 4.2 节的统一成果年份规则派生，不要求用户额外选择年份筛选依据。
3. 筛选后列表仅展示该年份的成果，按分类和月份倒序排列。
4. 年份筛选中可同时展示各年份的成果数量（可选增强项）。

## 9. 主界面统计（用户数据概览）

主界面展示“用户数据概览”，文案如下（`{班级名称}` 从系统配置读取）：

> 用户数据概览

> 根据您填报的信息，我们为您生成了如下的成果数据，您可以点击左侧其他栏目查看更详细的信息。  
> {班级名称}的发展离不开每一位同学的努力和付出，感谢您为{班级名称}做的一切，希望您继续进步，实现更大的成就!  
> 进入{班级名称}以来，您共填报了以下数据:学术论文*篇，竞赛获奖*项，科研项目*项，专利或软著*项，创新创业*项，组织管理*项，社会实践*项，文体活动*项。

要求：

1. 8 类数量分别展示，`*` 为实际数量。
2. 统计口径默认只统计审核通过（`approved`）的成果，作为正式档案数据；待审核、已拒绝不计入。如希望包含待审核数据，见“待确认事项”。
3. 班级名称使用系统配置（当前为“许国志大数据英才班”）。
4. 每类数量可点击跳转到“我的成果”对应分类（可选增强项）。

## 10. 数据模型与接口落地说明

### 10.1 数据模型

- `achievements` 表新增 `details_json`（Text/JSON 类型，默认空对象）。
- `achievement_date` 保持 `String(20)`，由模板年月派生为 `YYYY-MM`；不新增独立年份列，年份筛选基于 `achievement_date` 或 `details_json` 内年份字段实现。
- `proofs_json` 继续存储附件列表。
- `member_ids_json` 保留列，不再要求前端填写。

### 10.2 接口

- `AchievementCreate` / `AchievementUpdate` 新增可选字段 `details: dict` 和附件上传支持。
- 创建/更新接口按分类校验 `details` 必填键、枚举值和格式；校验失败返回具体字段错误。
- 详情和列表响应中返回 `details`，便于前端回显。
- 附件上传接口复用现有文件上传机制，上传后返回文件标识并写入 `proofs_json`。

### 10.3 前端

- 按 `category` 渲染动态模板表单，模板文案与字段严格按第 6 章执行。
- 是/否字段使用单选或开关控件；年份、月份使用数字输入；长文本使用多行输入。
- 表单顶部提供附件上传组件。
- 编辑时按 `details` 回显；旧数据无 `details` 时回退显示通用字段。

## 11. 校验规则汇总

| 规则 | 约束 |
| --- | --- |
| 必填 | 各模板全部条目必填；占位值“无”“forthcoming”视为已填写 |
| 是/否 | 仅允许“是”“否” |
| 年份 | 4 位数字，范围建议 1900 至当前年份 |
| 月份 | 1-12 |
| 项目经费 | 数字保留两位小数，或“无” |
| 引用次数 | 非负整数 |
| 页码 | 如 `20-30`，或 `forthcoming` |
| URL | WoS 链接必须为合法 URL |
| 人名列表 | 中文逗号分隔，去除首尾空格，不允许空项 |
| 附件 | 至少 1 份，格式建议 PDF/JPG/PNG |
| 顶刊认定 | AUTD24、FT50、ABS4 及以上、Nature、Science、Cell 系列 |

## 12. 待确认事项

以下事项用户未明确，本文档给出推荐默认值，评审时确认：

1. 主界面统计口径：推荐只统计审核通过（`approved`）的成果。
2. 项目课题、创新创业、组织管理、社会实践、文体活动中的“结束年份/结束月份”：进行中或仍在任时，推荐填写预计结束时间，或填“进行中”。
3. 软著专利未授权时：推荐授权年份/月份填“无”。
4. 论文类型：推荐固定为“期刊论文、会议论文”两类，是否增加“工作论文/其他”待确认。
5. 组织管理模板是否补充“职务”字段（当前模板未包含）。
6. 按年份查看的默认值：推荐默认当前年份，可切换“全部”。
7. 附件格式与大小上限：推荐 PDF/JPG/PNG，单文件不超过 20MB，可配置。

## 13. 验收要点

1. 8 类成果各自显示独立模板，字段与第 6 章一致，模板文案与用户提供文案一致。
2. 所有条目必填校验生效，“无”“forthcoming”等占位规则正确。
3. 附件可上传多份、展示、删除、替换，且为提交前提。
4. 我的成果可按年份筛选，默认当前年份，年份口径正确。
5. 主界面“用户数据概览”按 8 类正确统计并展示。
6. 创建、编辑回显、删除、提交审核、管理员审核流程不受影响。
7. 旧数据（无 `details_json`）可正常展示和编辑。
