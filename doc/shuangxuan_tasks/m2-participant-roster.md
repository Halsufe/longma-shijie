# M2 参与名单任务清单

> 来源：`../shuangxuan_proposal.md` 第 3、4.3、8.2、8.3 章；`../shuangxuan_high-level-design.md` 第 4.2、5.3 章  
> 目标：建立批次学生/导师参与关系、资格快照和开放前校验。  
> 依赖：M1 批次与状态机。  
> 说明：本模块接收 M9 解析后的标准化名单行，不负责具体文件格式解析。

## 最小可执行任务

### 数据与迁移

- [ ] M2-T01 在双选模型文件中新增 `MentorSelectionBatchStudent`，保存批次、学生、学号/姓名/班级快照和参与状态。
- [ ] M2-T02 新增 `MentorSelectionBatchMentor`，保存批次、教师、固定 `quota=4`、主选/补录匹配数和参与状态。
- [ ] M2-T03 为两张参与关系表增加 `(batch_id, user_id)` 联合唯一约束、必要外键和查询索引。
- [ ] M2-T04 创建并验证参与关系 Alembic 迁移的 upgrade/downgrade。

### 学生名单

- [ ] M2-T05 实现单行学生资格校验：学号存在、姓名一致、角色为 `student`、状态为 `active`、未软删除。
- [ ] M2-T06 实现标准化名单预检，返回行号、动作、错误码和中文错误，不在预检阶段落库。
- [ ] M2-T07 实现名单确认服务，在单事务中写入学生关系和快照，批次内重复学生不产生第二条记录。
- [ ] M2-T08 实现未开始批次移除学生能力；批次开始后拒绝移除。

### 导师名单与开放检查

- [ ] M2-T09 实现教师候选查询适配器，只返回有效 `teacher` 用户并组合其职称、院系和研究方向摘要。
- [ ] M2-T10 实现导师名单整体替换服务，固定写入 `quota=4`，批次开始后禁止替换。
- [ ] M2-T11 实现主选开放前校验：至少 1 名有效学生、至少 3 名有效导师，否则返回明确错误。
- [ ] M2-T12 实现补录开放前校验：剩余导师总名额必须不少于未匹配学生人数。

### 接口与验证

- [ ] M2-T13 新增管理员学生名单查询/移除、导师候选查询/保存参与导师接口。
- [ ] M2-T14 添加资格错误、快照稳定性、重复名单、导师最少人数、补录容量和阶段锁定测试。

## 模块完成定义

- [ ] M2-DO1 名单关系、快照、唯一约束和容量校验均由后端保证。
- [ ] M2-DO2 学生名单和导师名单接口仅管理员可用。
- [ ] M2-DO3 M2 专项测试、静态检查通过。
