# M5 导师选择任务清单

> 来源：`../shuangxuan_proposal.md` 第 6、9.5、10.3 章；`../shuangxuan_high-level-design.md` 第 4.5、5.5、6.3 章  
> 目标：实现候选学生查询、接收/拒绝、名单版本、最终提交和名额保护。  
> 依赖：M1、M2、M3、M4。

## 最小可执行任务

### 数据与迁移

- [ ] M5-T01 新增 `MentorDecisionSubmission` 模型，保存批次、导师、轮次、版本、保存时间和最终提交时间。
- [ ] M5-T02 新增 `MentorDecisionItem` 模型，保存候选学生和 `accepted/rejected` 决定。
- [ ] M5-T03 增加导师轮次版本唯一、同版本学生唯一、决定枚举约束和查询索引。
- [ ] M5-T04 创建并验证导师决定表 Alembic 迁移 upgrade/downgrade。

### 候选查询与决定服务

- [ ] M5-T05 实现候选查询，只读取正式提交且包含当前导师的学生，不返回草稿或已撤回志愿。
- [ ] M5-T06 通过 M3 组装候选详情，明确排除志愿排名、其他导师、其他导师理由和其他导师决定。
- [ ] M5-T07 定义导师决定保存、最终提交、详情和统计 Schema。
- [ ] M5-T08 实现决定草稿保存，允许在截止前反复生成新版本并保留历史。
- [ ] M5-T09 实现主选 `QuotaGuard`，同一导师 accepted 人数最多 4 人，可以少于 4 人或为空。
- [ ] M5-T10 实现补录 `QuotaGuard`，accepted 人数最多为 `4 - main_matched_count`。
- [ ] M5-T11 实现最终提交锁定；最终提交后拒绝修改，未最终提交时仍保留最后保存版本。
- [ ] M5-T12 实现导师截止快照服务，供 Worker 选取最终提交版本或最后保存版本。

### 接口与验证

- [ ] M5-T13 新增候选列表、候选档案、决定保存、最终提交、名额统计和导师结果查询接口。
- [ ] M5-T14 添加非参与导师、非本人候选、超额接收、空名单、最后保存版本、最终提交锁定和补录剩余名额测试。
- [ ] M5-T15 添加接口响应泄漏测试，断言导师响应中不存在 `rank`、其他导师 ID 和其他理由。

## 模块完成定义

- [ ] M5-DO1 每位导师每轮只有一个当前有效决定版本，历史可追溯。
- [ ] M5-DO2 主选与补录均无法通过并发请求突破累计 4 人上限。
- [ ] M5-DO3 M5 专项测试、静态检查通过。
