# M6 匹配与结果任务清单

> 来源：`../shuangxuan_proposal.md` 第 7、8.4、9.6 章；`../shuangxuan_high-level-design.md` 第 4.6、5.6、7.2 章  
> 目标：实现确定性的志愿顺序匹配、结果版本、发布条件、作废和角色化结果查询。  
> 依赖：M1、M4、M5。

## 最小可执行任务

### 数据与迁移

- [ ] M6-T01 新增 `MentorMatchResultVersion`，保存批次、轮次、版本、计算/发布/作废时间和状态。
- [ ] M6-T02 新增 `MentorMatchResultItem`，保存学生、可空导师、匹配志愿序号和 matched/unmatched 状态。
- [ ] M6-T03 增加结果版本唯一、同版本学生唯一和单轮单 published 结果约束及查询索引。
- [ ] M6-T04 创建并验证结果表 Alembic 迁移 upgrade/downgrade。

### 匹配与版本服务

- [ ] M6-T05 实现无数据库依赖的纯匹配函数：按学生分组 accepted 导师并选择 `rank` 最小者。
- [ ] M6-T06 为纯匹配函数加入输入不变量检查：学生至多一个结果、导师累计不超 4、导师必须属于当前批次。
- [ ] M6-T07 实现主选计算服务，锁定批次、志愿快照和导师决定，在单事务中创建不可变结果版本。
- [ ] M6-T08 实现主选不递补规则：学生选择高志愿后释放的名额只更新剩余名额，不重新选择被拒学生。
- [ ] M6-T09 实现补录计算服务，只处理主选未匹配学生和有剩余名额导师。
- [ ] M6-T10 实现补录发布守卫：存在任何 unmatched 时写阻塞状态并拒绝发布/完成。
- [ ] M6-T11 实现结果发布服务，保证同轮只有一个有效 published 版本并更新参与学生/导师统计。
- [ ] M6-T12 实现结果作废服务，重开时将现有有效版本标记 `void`，不物理删除。

### 查询、汇总与验证

- [ ] M6-T13 实现学生本人结果查询，只返回本人当前有效导师或未匹配状态。
- [ ] M6-T14 实现导师结果查询，只返回最终匹配自己的学生。
- [ ] M6-T15 实现管理员只读汇总：志愿、导师决定、匹配结果、名额使用、提交率和未匹配名单。
- [ ] M6-T16 添加多导师接收按志愿选择、无接收未匹配、主选不递补、补录容量和全部匹配门禁单元测试。
- [ ] M6-T17 添加重复计算、重复发布、结果作废、角色结果可见性和并发配额集成测试。

## 模块完成定义

- [ ] M6-DO1 相同输入始终产生相同匹配结果，算法不依赖查询返回顺序。
- [ ] M6-DO2 补录未全部匹配时不存在可见的有效最终发布版本。
- [ ] M6-DO3 M6 专项测试、静态检查通过。
