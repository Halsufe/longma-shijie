# M3 学生档案适配任务清单

> 来源：`../shuangxuan_proposal.md` 第 3.1、5.1、6.1、13.2 章；`../shuangxuan_high-level-design.md` 第 4.3、5.8 章  
> 目标：扩展学生资料并提供严格授权的候选档案、成果和证明附件读取边界。  
> 依赖：M1、M2，现有 `profile_service`、成果服务和文件服务。

## 最小可执行任务

### 个人资料

- [ ] M3-T01 在用户 Schema 中新增 `phone`、`email`、`course_grades` 白名单字段，保持旧 `profile_json` 可读。
- [ ] M3-T02 定义课程成绩项 Schema，要求 `course_name` 和 `score` 非空，`remark` 可选，不限制课程名称和成绩表达形式。
- [ ] M3-T03 在 `profile_service.py` 实现手机号、邮箱和课程成绩结构校验，不新增 GPA 字段。
- [ ] M3-T04 更新本人资料接口，使学生可保存手机号、邮箱和任意课程成绩列表。
- [ ] M3-T05 实现双选正式提交前档案完整性校验：个人简介必填、课程成绩至少 3 条；手机号和邮箱按需求保持可选但有值时必须合法。

### 档案适配与权限

- [ ] M3-T06 实现 `TeacherResourceAdapter`，只输出姓名、职称、院系、简介、研究方向和方向标签。
- [ ] M3-T07 实现 `StudentProfileAdapter`，只输出导师获准查看的姓名、学号、班级、专业、手机号、邮箱、简介和课程成绩。
- [ ] M3-T08 实现 `AchievementArchiveAdapter`，只查询候选学生 `status=approved` 的成果。
- [ ] M3-T09 实现 `CandidateProfilePolicy`：选择阶段仅对应导师可看选择自己的学生，管理员可看全部。
- [ ] M3-T10 实现发布后权限收回：导师只能继续查看最终匹配自己的学生。
- [ ] M3-T11 为成果证明附件增加双选访问校验，复用现有文件响应且不暴露物理存储路径。
- [ ] M3-T12 在档案与附件查看路径接入 M8 审计适配接口；M8 未完成前先提供可替换的服务边界。

### 验证

- [ ] M3-T13 添加旧 profile 兼容、课程自由填写、少于 3 门拒绝、非法手机号/邮箱测试。
- [ ] M3-T14 添加候选导师可见、其他导师不可见、志愿顺序不泄漏、发布后权限收回和附件越权测试。

## 模块完成定义

- [ ] M3-DO1 API 不直接返回完整 `profile_json`，敏感字段只经适配器输出。
- [ ] M3-DO2 导师只能查看授权学生的已审核成果和证明附件。
- [ ] M3-DO3 M3 专项测试、静态检查通过。
