# M5 相关性、去重与更新识别任务清单

> 模块目标：筛选学生相关公告，完成同源幂等、跨来源保守合并，并区分普通修订与关键更新。  
> 前置依赖：M4 标准化文本；M6 AI 调用接口；M7 公告 Repository。  
> 主要目录：`backend/app/announcements/dedup.py`、`backend/app/services/announcement_relevance_service.py`

## 最小可执行任务

- [ ] **M5-T01 定义相关性三态模型**：支持 `relevant/irrelevant/uncertain`、置信度和依据；添加枚举及验证测试。
- [ ] **M5-T02 实现确定性排除词规则**：覆盖采购、招标、自采、教师招聘、职称、导师遴选、校外招生宣传、新闻、喜报和活动回顾。
- [ ] **M5-T03 添加排除规则反例测试**：确保标题含“教师”但面向学生选课等公告不会被简单关键词误杀。
- [ ] **M5-T04 实现 AI 相关性分类提示词与解析**：输入标题、正文、单位和附件文本，输出三态结果；AI 失败返回 `uncertain`。
- [ ] **M5-T05 实现相关性决策编排**：确定性明确排除优先，其余调用 AI；`relevant/uncertain` 可见，`irrelevant` 仅计数。
- [ ] **M5-T06 实现标题规范化**：统一空白、全半角、标点和固定栏目标签，不移除具有业务意义的日期及编号。
- [ ] **M5-T07 实现内容指纹**：对清洗正文、附件文本和关键元数据生成稳定 SHA-256；空白和排版变化不产生新指纹。
- [ ] **M5-T08 实现同源匹配**：按 `source_id + canonical_url` 查找来源记录，重复轮询只更新 `last_seen_at`。
- [ ] **M5-T09 实现跨源候选查询**：仅在官网发布日期相同的公告中查找标题相似候选，限制候选数量。
- [ ] **M5-T10 实现保守标题相似度算法**：阈值配置化；冲突或低置信度时不合并；用真实风格标题样本测试。
- [ ] **M5-T11 实现跨源合并事务**：锁定目标公告并新增来源映射，唯一冲突时回读已有结果。
- [ ] **M5-T12 定义关键字段规范化**：规范比较标题、适用对象、截止时间、地点和待办事项，减少格式差异误报。
- [ ] **M5-T13 实现更新分类器**：内容指纹变化后区分普通修订和关键更新，保存变更字段及 `key_updated_at`。
- [ ] **M5-T14 实现同窗口多次更新折叠**：公告只以最新状态进入一次汇总。
- [ ] **M5-T15 添加幂等与并发测试**：覆盖相同 URL 并发插入、跨源并发合并、误合并保护和重复更新。

## 完成条件

- [ ] AI 分类失败时公告保留为 `uncertain`，不造成漏报。
- [ ] 同源重复和可信跨站转载不会产生重复用户公告。
- [ ] 只有关键字段实质变化才进入下一次汇总并标记“已更新”。
