# M6 AI 摘要与降级任务清单

> 模块目标：复用现有 AI 适配器生成有原文依据的结构化摘要，严格校验输出，并在失败时生成可推送的降级摘要。  
> 前置依赖：M4 提供正文与附件文本；M7 保存结果。  
> 主要目录：`backend/app/services/announcement_summary_service.py`、`backend/app/schemas/announcement.py`

## 最小可执行任务

- [ ] **M6-T01 定义摘要输出 Schema**：包含摘要、发布单位、适用对象、关键时间、截止时间、地点和待办事项；空字段统一为 `null` 或空数组。
- [ ] **M6-T02 编写公告摘要系统提示词**：要求摘要 100～200 汉字、禁止推测、只从输入提取字段、返回严格 JSON。
- [ ] **M6-T03 实现输入组装与长度控制**：按网页正文优先、附件文本补充的顺序截取，保留标题和来源，避免超过模型上下文。
- [ ] **M6-T04 实现非流式 AI 调用**：复用 `get_adapter().chat`，记录模型名、耗时和安全错误摘要。
- [ ] **M6-T05 实现 JSON 提取与 Pydantic 校验**：兼容代码围栏，拒绝类型错误、额外危险字段和空摘要。
- [ ] **M6-T06 实现一次格式修复请求**：仅在内容存在但结构不合法时尝试一次，不对网络失败无限重试。
- [ ] **M6-T07 实现摘要长度处理**：过长时重新压缩或安全截断，过短但有效时保留并记录质量状态。
- [ ] **M6-T08 实现字段证据校验**：时间、地点、单位和待办事项必须能在输入文本中找到对应片段；无依据字段置空。
- [ ] **M6-T09 实现正文降级摘要**：AI 失败时使用清洗后正文前 200 个汉字并标记 `degraded`。
- [ ] **M6-T10 实现附件降级摘要**：正文为空时使用成功解析附件文本前 200 个汉字。
- [ ] **M6-T11 实现最小摘要**：正文和附件均无文本时使用标题与来源，公告仍可进入汇总。
- [ ] **M6-T12 实现摘要结果持久化接口**：原子更新结构化字段、模型、状态、错误摘要和更新时间。
- [ ] **M6-T13 实现手动重摘要入口服务**：接收公告 ID，复用同一管线，不直接产生用户通知。
- [ ] **M6-T14 添加 Mock AI 测试集**：覆盖正常 JSON、代码围栏、幻觉字段、超长、空响应、错误字符串、超时和格式修复。
- [ ] **M6-T15 添加降级验收测试**：验证三层降级顺序、动态空字段隐藏数据和管理员降级计数。

## 完成条件

- [ ] 正常 AI 摘要满足 100～200 汉字目标，结构化字段通过 Schema 校验。
- [ ] 无原文依据的字段不会持久化或展示。
- [ ] 任意 AI 故障都能落入明确降级状态且不阻断公告推送。
