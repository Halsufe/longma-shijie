# M11 数据清理任务清单

> 模块目标：按官网发布日期清理超过 30 天的公告业务数据和临时文件，同时永久保留汇总快照及站内通知。  
> 前置依赖：M2 调度、M7 数据模型。  
> 主要目录：`backend/app/workers/announcement_cleanup.py`

## 最小可执行任务

- [ ] **M11-T01 固化到期时间算法**：官网发布日期当天为第 1 天，第 30 个自然日结束后过期；使用 `Asia/Shanghai` 测试月末和年末。
- [ ] **M11-T02 实现到期候选查询**：只返回已过期公告，按 ID 分批并限制每批数量。
- [ ] **M11-T03 实现过期状态流转**：清理前将公告标记为 `expired`，避免继续进入查询或汇总。
- [ ] **M11-T04 实现公告详情清理事务**：删除正文、结构化字段、附件解析文本、附件和来源映射等业务数据。
- [ ] **M11-T05 保留汇总快照和通知**：清理不级联删除 `announcement_digests`、投递记录或 `notifications`；添加外键回归测试。
- [ ] **M11-T06 处理公告主记录生命周期**：按数据模型决定硬删公告主记录或保留最小墓碑，确保汇总快照不依赖该记录。
- [ ] **M11-T07 实现临时目录兜底清理**：只删除公告专用临时目录中超过 TTL 的文件，校验绝对路径边界。
- [ ] **M11-T08 实现分批提交与续跑**：单条失败不阻断后续项，重试不会误删 30 天内数据。
- [ ] **M11-T09 写入清理任务统计**：记录扫描、过期、删除、跳过和失败数量及耗时。
- [ ] **M11-T10 接入 M2 每日调度**：使用稳定任务键和租约，避免并发清理。
- [ ] **M11-T11 实现手动测试入口服务**：仅测试/管理内部调用，可传入基准时间，不开放任意路径参数。
- [ ] **M11-T12 添加保留期边界测试**：第 29、30、31 天，未来日期，错误日期和时区午夜。
- [ ] **M11-T13 添加数据完整性集成测试**：清理后工作台不可见，历史汇总可读，原通知未删除且外链快照仍在。
- [ ] **M11-T14 添加文件安全测试**：临时清理不得越过公告临时根目录，不跟随符号链接删除外部文件。

## 完成条件

- [ ] 第 30 个自然日结束前公告仍可见，次日按批次清理。
- [ ] 历史汇总快照、投递记录和站内通知不受公告清理影响。
- [ ] 清理可重复执行且不会删除范围外文件或未到期数据。
