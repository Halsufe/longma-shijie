# M2 调度与任务编排任务清单

> 模块目标：在独立 Worker 中可靠触发轮询、汇总、清理、初始化和人工任务，使用 PostgreSQL 租约与任务键实现恢复和幂等。  
> 前置依赖：M7 任务实体与 Repository；业务执行分别依赖 M1、M8、M10、M11。  
> 主要目录：`backend/app/workers/announcement_worker.py`、`backend/app/workers/announcement_scheduler.py`

## 最小可执行任务

- [ ] **M2-T01 增加 Worker 配置 Schema**：加入启用开关、时区、轮询间隔、汇总小时、租约时长和心跳间隔；验证默认值和非法值。
- [ ] **M2-T02 定义稳定任务键生成器**：分别生成轮询、每日汇总、清理、初始化和人工任务键；测试同一窗口稳定、不同窗口不冲突。
- [ ] **M2-T03 实现任务状态流转服务**：支持 `pending -> running -> success/partial_success/failed`，拒绝非法倒退；添加状态机测试。
- [ ] **M2-T04 实现 PostgreSQL advisory lock 封装**：支持获取、释放和异常退出清理；SQLite 测试使用可替换的单进程锁实现。
- [ ] **M2-T05 实现任务认领与租约**：原子认领 `pending` 或租约过期任务，写入执行者和心跳；添加双执行者竞争测试。
- [ ] **M2-T06 实现心跳更新**：长任务按配置刷新 `heartbeat_at`，任务结束或取消时停止；使用短间隔测试验证。
- [ ] **M2-T07 实现每 30 分钟轮询调度**：APScheduler 以 `Asia/Shanghai` 注册 cron/interval 任务，触发时只创建并执行唯一任务记录。
- [ ] **M2-T08 实现 20:00 边界编排**：先完成边界轮询，再调用每日汇总；测试统计窗口为起点不含、终点包含。
- [ ] **M2-T09 实现每日清理调度**：在低峰期创建唯一清理任务并调用 M11，不与轮询共享长事务。
- [ ] **M2-T10 实现人工任务轮询器**：认领管理 API 创建的重抓、重试、重解析和重摘要任务并分派到对应服务。
- [ ] **M2-T11 实现启动恢复扫描**：找出最后成功汇总之后所有已结束窗口，并按日期升序交给 M8 分别补发。
- [ ] **M2-T12 实现恢复后立即轮询**：历史窗口补发完成后执行一次采集，新发现公告使用恢复时的首次发现时间。
- [ ] **M2-T13 实现任务统计聚合**：记录发现、创建、更新、合并、跳过、失败、降级和耗时数据。
- [ ] **M2-T14 实现独立 Worker CLI 入口**：支持启动、优雅停止和退出码；Web 应用启动时不得注册公告调度器。
- [ ] **M2-T15 添加并发与崩溃恢复集成测试**：覆盖双 Worker、租约过期、执行中退出、任务重试和重复调度。

## 完成条件

- [ ] 同一任务窗口并发触发时仅有一个有效执行者。
- [ ] 连续遗漏多个 20:00 窗口时按日期分别补发。
- [ ] Worker 重启不会丢失数据库中的待执行或部分完成任务。
