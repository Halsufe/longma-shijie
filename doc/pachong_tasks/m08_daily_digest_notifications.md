# M8 每日汇总与通知任务清单

> 模块目标：生成固定 24 小时窗口的不可变汇总快照，并向不超过 1000 个 active 用户幂等发送一条站内通知。  
> 前置依赖：M2 调度、M7 数据访问、现有通知中心。  
> 主要目录：`backend/app/services/announcement_digest_service.py`、`backend/app/services/notification_service.py`

## 最小可执行任务

- [ ] **M8-T01 实现北京时间窗口计算器**：给定执行日期生成前日 20:00（不含）至当日 20:00（含）；覆盖夏令时无关和日期跨月测试。
- [ ] **M8-T02 实现汇总候选查询**：包含窗口内首次发现公告及关键更新公告，排除过期、无关和失败公告。
- [ ] **M8-T03 实现同窗口公告折叠与排序**：同一公告只出现一次，标记新增或已更新，按关注时间倒序稳定排序。
- [ ] **M8-T04 定义摘要快照 Schema**：保存标题、精简摘要、来源、日期、状态、原文和附件链接，不依赖后续公告表。
- [ ] **M8-T05 实现通知文案生成器**：有公告时生成数量与精简清单，无公告时生成“今日无新通知”。
- [ ] **M8-T06 实现唯一汇总创建**：按 `window_start + window_end` 创建或回读，快照生成后不可因普通重试被改写。
- [ ] **M8-T07 实现接收人查询**：仅 `status=active AND deleted_at IS NULL`，涵盖所有角色；添加用户状态矩阵测试。
- [ ] **M8-T08 扩展通知路由约定**：使用 `type/ref_type=school_announcement_digest`、`ref_id=digest.id`。
- [ ] **M8-T09 实现分批投递**：按配置批次批量插入投递记录和通知，单批事务提交，支持 1000 用户。
- [ ] **M8-T10 实现投递幂等**：利用 `(digest_id, user_id)` 唯一键跳过已成功用户，不依赖进程内集合。
- [ ] **M8-T11 实现部分失败恢复**：汇总状态记录成功/失败数量，重试只处理 `pending/failed` 用户。
- [ ] **M8-T12 实现无公告投递测试**：确认空快照也为每个 active 用户创建且只创建一条通知。
- [ ] **M8-T13 实现边界轮询协调**：20:00 汇总只在该边界轮询成功或达到明确超时后开始，并记录数据完整性状态。
- [ ] **M8-T14 实现遗漏窗口扫描**：从最后完成窗口到最近已结束窗口逐日生成待补发列表。
- [ ] **M8-T15 实现按日期分别补发**：每个遗漏窗口各自生成汇总和通知，标记 `is_recovery=true`。
- [ ] **M8-T16 实现停机数据限制提示**：恢复告警说明停机期间未发现公告会进入恢复后的新窗口，而非伪造历史首次发现时间。
- [ ] **M8-T17 添加 1000 用户性能测试**：验证批量插入时间、事务大小和通知未读计数正确。
- [ ] **M8-T18 添加全链路幂等测试**：覆盖重复调度、投递中断、数据库冲突、连续补发和公告清理后快照读取。

## 完成条件

- [ ] 每个窗口、每个 active 用户最多一条公告汇总通知。
- [ ] `pending_change`、`disabled` 和软删除用户不接收通知。
- [ ] 公告业务数据清理后，历史汇总快照和通知内容仍可读取。
