# 导师双选、党建与 AI 对话优化设计

## 目标

移除前端学校公告入口与首页公告区；分别优化导师双选页和党建页的首屏信息层级与响应式布局；将后端 AI 配置更新为用户提供的新密钥，并保留真实网络失败时的明确错误反馈。

## 范围

- 删除前端侧栏中的“学校公告”、`announcements` 路由、公告视图加载，以及首页公告面板和对应请求。
- 保留后端公告路由、采集逻辑、数据库表和数据，避免无关的数据迁移风险。
- 保持导师双选与党建为两个独立路由页面。导师双选页内部继续保留“导师双选 / 研究方向与学习计划”工作区切换。
- 导师双选采用“任务工作台”：批次状态摘要、主任务列表、个人志愿或待处理事项分栏；移动端改为单列。
- 党建采用“活动工作台”：政治面貌与记录摘要、筛选条、活动主列表、学习资料与参与记录侧栏；移动端改为单列。
- AI key 只写入后端 `.env` 的 `AI_API_KEY`，不进入任何前端静态资源或 API 响应。
- AI 请求仍通过现有 `GenericAdapter`；当前环境到 `api.deepseek.com:443` 的 TCP 连接失败属于外部网络/代理问题，代码不伪造成功响应。

## 设计原则

1. 复用现有 `pageHeader`、`panel`、`stats-grid`、`toolbar`、`resource-card` 和按钮体系，减少风格漂移。
2. 先呈现用户需要做的下一步，再呈现辅助资料；不把两个业务模块塞进同一页。
3. 保持现有 API、权限、报名、签到、志愿提交、草稿和管理员流程不变，只改变 HTML 组织和 CSS。
4. 交互控件必须在桌面和移动端都可达，文本不得被截断或遮挡。

## 页面结构

### 导师双选

- 页头显示批次名称、学年学期和当前阶段。
- 状态摘要显示当前轮次、发布时间/截止时间和关键进度。
- 学生填报阶段：主区域为导师列表及筛选；侧栏为个人陈述、当前志愿和提交操作。
- 等待/发布阶段：主区域显示阶段说明或匹配结果，侧栏显示相关时间和后续提醒。
- 教师和管理员使用同一容器规则，但保留现有角色专属操作与数据。

### 党建

- 页头后紧接政治面貌、待参加活动数、年度参与记录摘要。
- 筛选条固定在活动列表上方，状态、类别、年份和筛选按钮在窄屏时纵向排列。
- 主区域展示活动列表及报名、取消、签到、详情操作。
- 侧栏展示政治学习资料和我的参与记录；完整党员档案保留在下方独立区域。
- 现有政治面貌申请、资料下载和活动详情弹窗保持原行为。

## AI 配置与错误处理

- 更新 `AI_API_KEY`，保持 `AI_BASE_URL=https://api.deepseek.com` 与 `AI_MODEL=deepseek-chat`。
- 不在 `frontend/`、HTML、浏览器存储或可读 API 响应中写入密钥。
- 继续使用现有连接、读取、写入和连接池超时；错误文案按 HTTP 状态、超时、连接失败分类。
- 验证时分别检查本地 `/health`、聊天接口到适配器的错误路径和配置加载报告；外网不可达时记录为环境限制，不将其误报为代码修复成功。

## 验证

- 运行公告、页面、布局和聊天前端契约测试。
- 运行 Python 编译/导入检查，确保删掉公告导入后没有未定义引用。
- 启动现有 FastAPI 服务，检查首页、导师双选和党建页面 DOM；检查桌面与移动端关键布局类和控制台错误。
- 对聊天发送一次测试消息，确认失败时显示可读错误而不是未处理异常；若网络恢复，再确认真实回复链路。
